# Local File Organizer

整理的交付物不是“看起来整齐”，而是一个可解释、可回滚、能继续维护的系统。

## 选择分支

只走用户需要的分支，完成后即停止：

- **盘点**：只读检查并给出结构、命名与清理方案。
- **执行**：在盘点后按已授权的变更账本移动、重命名或去重。
- **复盘**：仅在用户明确要求时，从已检查的材料提炼人生与工作线索。读取
  [复盘规则](references/reflection.md)；不因整理文件而自动生成。

## 安全契约

- 先解析目标的绝对路径、排除项与每个空间的用途。现有目录是线索，不是分类真相。
- 默认保持可逆。把不确定项放入 `Review` 或 `PendingDelete`；可用系统废纸篓时优先使用。
- 把代码仓库、应用包、照片图库、设计工程、媒体项目、依赖目录和其他自包含包视为一个
  单元，除非用户明确要求拆包。
- 标出符号链接、硬链接、云端占位文件、权限边界及跨卷移动；不要把它们当普通文件处理。
- 只读取完成分类所需的最少内容。报告中省略证件号、地址、账户、健康、合同等敏感细节。
- 永久删除需要对当前清单中明确类别的单独授权。“清理一下”不构成删除授权。
- 跨卷或云盘操作先复制并验证，再处理源文件；目标未验证前，源文件保持不变。

## 工作流

### 1. 建立空间契约

为每个根目录确定一个主要职责，例如 `CurrentWork`、`Inbox`、`Archive`、
`MediaWork` 或 `PersonalVault`。若职责无法从请求中可靠判断，用普通文本给出 2–3 个
方案，标注推荐项及一句取舍。

记录：

- 目标与排除路径
- 空间职责
- 用户要盘点、执行还是复盘
- 可接受的改名、移动与删除范围

完成标准：每个根目录只有一个主要职责，边界与授权无歧义。

### 2. 建立证据清单

先只读盘点。按需检查路径、名称、类型、逻辑大小、修改时间、元数据和可读内容；先识别
用途，再设计归宿。

- 独立文件按实际用途分类；自包含包保持完整。
- 大量同质文件可以按可解释的规则分组抽样，并记录规则、数量和未逐项检查的范围。
- 决定删除时不得依赖抽样。
- 文件名相似只产生“疑似重复”；大小一致并经内容哈希确认后才是“完全重复”。
- 相似照片、不同导出、版本稿和项目内副本是独立审查项，不并入完全重复。

完成标准：范围内每个项目都被逐项记录，或落入有证据规则和数量的分组；未读、敏感、
异常与排除项均有标记。

### 3. 设计结构与变更账本

每层目录只采用一个主要检索轴：

1. 根层按空间职责；
2. 下一层按领域或项目；
3. 只有当时间是主要检索方式时，才按时间分层。

沿用用户已有的简洁命名风格。仅在确实需要固定排序或双语识别时使用
`NN_EnglishTag_中文说明`；日期目录使用 `YYYYMMDD_主题`。

先提交目标树和变更账本。账本至少包含：

| ID | 动作 | 来源 | 目标 | 依据 | 风险/可逆性 | 逻辑大小 |
|---|---|---|---|---|---|---|

另列：

- 完全重复、疑似重复、生成物/缓存、过期候选；
- 命名冲突、包边界、跨卷或云端项目；
- 明确保留、暂不处理与需要确认的项目；
- 回滚方法及预计待释放空间。

完成标准：每个动作都有唯一目标；覆盖、同名冲突和高风险项已有处理决定；所有未决项保持
不动。

### 4. 通过授权门

- 用户只要求盘点或方案：保持只读。
- 用户已明确要求执行，且账本完全落在已确认边界内：可执行可逆动作。
- 范围、归类策略或目标位置发生实质变化：先确认更新后的账本。
- 永久删除：展示具体类别、文件数、路径范围与逻辑大小，取得单独授权后才执行。

授权只覆盖当前账本。新增动作回到本步骤。

### 5. 分批执行并核验

在首个变更前，把账本保存到目标空间或用户指定的持久日志位置。随后：

1. 检查目标卷空间、写权限、目标不存在覆盖冲突；
2. 创建目标目录；
3. 小批量执行低风险移动和改名，每批更新账本；
4. 跨卷文件复制后核对数量、大小；关键文件或完全重复再核对哈希；
5. 对不确定项保留相对路径，移动到审查区；
6. 遇到目标变化、校验失败、权限异常或未计划冲突时，停止受影响批次。

遇到覆盖冲突时保留源与目标并记录；按账本状态区分部分成功与全部成功。

完成标准：账本中每项都有 `完成`、`失败` 或 `未执行` 状态；完成项的目标实际存在，
跨卷复制已验证，失败项的源文件仍可恢复。

### 6. 结账

报告：

- 已完成、失败、未执行与刻意保留的数量和位置；
- 完全重复、疑似重复及删除候选的处理结果；
- 回滚或从废纸篓恢复的方法；
- 新结构的使用规则和最小下一步。

区分空间口径：

- 文件仍在磁盘、审查区或废纸篓：`待释放空间`；
- 已经永久移除：`已删除的逻辑大小`；
- 只有经过文件系统测量，才称为`实际释放空间`。
