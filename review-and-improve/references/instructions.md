# Skill And Instruction Repair

Inspect the authoritative source and governing rules. Match the remedy to the
observed failure:

- **Discovery:** a visible skill should have triggered but did not; tune its
  description and test matching and adjacent requests.
- **Placement:** useful guidance was buried or weak; clarify or move it instead
  of adding another copy.
- **Drift:** a fact or recipe no longer matches its owner; repair the source and
  execute the affected workflow.
- **Execution:** clear guidance was ignored; investigate execution or enforceable
  controls before appending the same instruction.

Keep source skills as the owner of reusable workflows. Global agent files carry
minimal navigation pointers; reviewer standards carry judgement calls. Check
existing documentation before adding another fact store. One-off task choices
and assistant guesses do not become global preferences.

For a trivial edit, change the existing source directly. For substantial edits,
description tuning or a justified new skill, use the host's skill authoring
workflow when available; otherwise perform the same draft, run and iterate loop.
Keep naming and UI metadata aligned with invocation policy. New skills require
a recurring pattern with no adequate existing owner.

Use familiar leading words, one source of truth and conditional references.
Prune stale, duplicate and demonstrated no-op instructions; retain real
constraints. Validate syntax, links and metadata. For meaningful behavior
changes, compare against the previous version on realistic requests, including
requests that should leave the skill unused; rerun a fresh case after repairs.
Report unmeasured effects rather than claiming improvement from wording alone.
