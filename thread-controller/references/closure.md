# Completion, settle, and handoff

Use for completion, checkpoint, settle, or handoff decisions about assigned
work, including claims whose acceptance would release a dependency.

Compare the claim with the overall assignment, the user's latest intent, and
available results. Reuse valid delivery and verification evidence; investigate
material gaps or contradictions. A title change alone does not call for another
review, test run, or approval.

For final completion, verify that the agreed outcome is delivered and check
whether any required acceptance, push, publication, or user action remains.
Optional follow-ups and unrelated work can remain without keeping the finished
task open.

Use a checkpoint state when the user or task defines an intermediate milestone
and work is parked there. Ordinary progress stays active without inventing a
checkpoint.

Distinguish **settling** from **archiving** when the host supports both:

- **Settle:** clear a verified completed thread or finished branch from active
  attention while preserving full history and easy recovery (`unsettle`) if
  follow-up is needed.
- **Archive:** retire accepted predecessors, confirmed duplicates, or threads
  explicitly chosen for archival retention.

A handoff transfers remaining responsibility after the successor accepts it. For
coordinator succession, use [handoff.md](handoff.md) for acceptance and routing.

When new evidence challenges a completion claim, reassess the task and reflect
the remaining work accurately. Where evidence is unclear, state what is verified
and what remains to check.
